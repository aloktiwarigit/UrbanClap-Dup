## Round 1 — 2026-09-06, reviewed `8148919a`

Verdict: *"The new synchronous completion path can steal receivable creation from the change-feed trigger and thereby suppress existing completion side effects, and it also applies cash receivable logic to Razorpay bookings. These are functional ledger/business-flow regressions."*

| # | Sev | Finding | Resolution |
|---|---|---|---|
| 1 | P1 | `active-job.ts` creates the receivable before the change-feed trigger runs, so the trigger sees `created: false` and skips `COMMISSION_DUE_RECORDED`, `incrementCompletedJobCount` and the `EARNINGS_UPDATE` push on every normal completion. | Side effects moved into `settleCashCompletion(booking)` in `commission-settlement.service.ts`, which owns audit + increment + FCM on `created: true` and always finalises the ledger. Both callers (trigger and active-job) use it. Exactly-once property test added. |
| 2 | P1 | The same call records a cash-style receivable for `paymentMethod: 'RAZORPAY'` bookings, alongside the Razorpay payout path. | `recordCommissionDue` returns `skipped: 'NOT_CASH'` for Razorpay before the cascade, so neither caller can raise a cash receivable on a prepaid booking. |

Fixed in `6d018dfd`.
