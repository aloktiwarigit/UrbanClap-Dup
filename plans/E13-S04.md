## Architecture overview

The credit-apply flow requires changes at three layers:

1. **Domain models** — `BookingRequest.applyCredit`, `BookingResult.appliedCreditAmount`
2. **Data layer** — DTO fields + repository mapping
3. **UI layer** — BookingSummaryScreen toggle + BookingViewModel state + BookingConfirmedScreen banner

The wallet balance flows from `FeatureFlags.walletVisible()` + a `GetWalletBalanceUseCase` call into
`BookingViewModel`, which exposes `walletBalanceInPaise` and `applyCreditToggle`. The UI observes these
to show/hide the toggle and compute the display total.

## Security invariants
- `applyCredit` is a client hint only; server determines actual credit deducted.
- `appliedCreditAmount` from API response drives the confirmation banner.
- Display total: `max(0L, originalAmountPaise - walletBalanceInPaise)` when toggle on.
- Razorpay order amount: `response.amount - response.appliedCreditAmount` (both from server).

## WS-B: ViewModel + UI state

### B1: BookingUiState
- `Ready` — add `walletBalanceInPaise: Long = 0L`
- `BookingConfirmed` — add `appliedCreditAmount: Int = 0`

### B2: BookingViewModel
New state and API:
```
private val _walletBalanceInPaise = MutableStateFlow(0L)
public val walletBalanceInPaise: StateFlow<Long>

private val _applyCreditToggle = MutableStateFlow(false)
public val applyCreditToggle: StateFlow<Boolean>

public fun setWalletBalance(paise: Long)
public fun setApplyCreditToggle(checked: Boolean)
```

- `setWalletBalance(paise)` sets internal balance and auto-enables toggle if paise > 0.
- `startBooking` reads `_applyCreditToggle.value` to set `applyCredit` in `BookingRequest`.
- `AwaitingPayment.amount` is set to `result.amount - result.appliedCreditAmount` (the reduced Razorpay amount).
- `BookingConfirmed` carries `appliedCreditAmount` from the result.

### B3: Tests — BookingViewModel
- Toggle auto-enabled when balance > 0; stays off when balance == 0.
- `applyCredit = true` forwarded to `createBooking` when toggle on.
- `AwaitingPayment.amount` = original − appliedCreditAmount.
- `BookingConfirmed.appliedCreditAmount` populated.
- Toggle off: full original amount used.
- Security: credit cannot make total go below 0 (Razorpay guard).

## WS-D: UI — BookingConfirmedScreen

### D1: Add `appliedCreditAmount: Int = 0` parameter
When `> 0`, show a Surface chip: "₹X credit applied" with `MaterialTheme.colorScheme.tertiaryContainer`.

### D2: Wire into confirmedDestination (MainGraph)
Read `appliedCreditAmount` from navigation arg or from BookingViewModel's last confirmed state.

**Implementation decision:** rather than threading through navigation args (complex), expose
`lastAppliedCreditAmount: Int` from `BookingViewModel` — the confirmed destination reads from the
same ViewModel instance (scoped to booking graph) and passes it to `BookingConfirmedScreen`.
