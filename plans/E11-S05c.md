## Prerequisites

This story does NOT introduce the `pending_actions` Room table, `PendingActionDao`, `PendingActionsDatabase`, `PendingActionIngestor`, or `PendingActionStore` — all exist from E11-S01a-2.

This story does NOT introduce `KycOrchestrator`, `DigiLockerConsentUseCase`, `PanOcrUseCase`, `FirebaseStorageUploader`, `DigiLockerCallbackBus`, `KycRepository`, or `KycScreen` — all exist from prior KYC stories.

`PendingActionType` already contains `KYC_RESUME`. This story adds three onboarding-specific variants to that enum (one of which reuses the existing `KYC_RESUME` semantics for DigiLocker resumption).

What this story adds on top of that foundation:

- Two new `PendingActionType` constants: `KYC_SUBMIT_PENDING`, `PHOTO_UPLOAD_RETRY` (join the existing `KYC_RESUME`).
- A `KycStatusEventBus` for in-process propagation of FCM-delivered KYC verdict events.
- FCM branches in `HomeservicesFcmService` for `KYC_VERIFIED`, `KYC_REJECTED`, and `ONBOARDING_REMINDER`.
- `KycViewModel` extension: consume `KycStatusEventBus`; expose `photoUploadRetryPending` flag derived from Room.
- A `PhotoUploadRetryBanner` composable surfaced inside `KycScreen` when `PHOTO_UPLOAD_RETRY` is active in Room.
- `OnboardingScreen` wiring: show a status chip when `KYC_SUBMIT_PENDING` is in Room (upload queued offline).
- EN + HI strings for all new UI surfaces.

**libs.versions.toml sync** — first task: copy `customer-app/gradle/libs.versions.toml` to
`technician-app/gradle/libs.versions.toml` before writing any code.

## Architecture overview

### Onboarding ops survive backgrounding

```
Technician submits PAN photo
  └─ KycOrchestrator.submitPan(uri, techId)
       failure (offline / network) → PendingActionType.PHOTO_UPLOAD_RETRY row inserted to Room
                                      entityId = technicianId, priority = HIGH

Technician taps DigiLocker → Custom Tab launched
  └─ App goes to background (process may die)
  └─ Deep-link returns homeservices://kyc/aadhaar-callback?code=<authCode>
       └─ MainActivity receives intent, posts authCode to DigiLockerCallbackBus [existing]
       └─ KycViewModel collector resumes and exchanges code [existing]
       failure (network on resumption) → PendingActionType.KYC_RESUME row inserted
                                         (matches existing FCM type; used for queue durability)

Connectivity restored → ConnectivityObserver.isConnected emits true
  └─ KycViewModel.init collector → retries any PHOTO_UPLOAD_RETRY rows for this techId
  └─ KycViewModel.init collector → retries any KYC_RESUME rows (re-triggers exchangeAadhaarCode)

FCM: backend confirms outcome
  └─ KYC_VERIFIED / KYC_REJECTED → HomeservicesFcmService new branch [WS-B]
       ├─ kycStatusEventBus.post(KycStatusEvent(…))   [NEW in WS-A]
       ├─ PendingActionIngestor.ingest resolves PHOTO_UPLOAD_RETRY + KYC_RESUME rows
       └─ system-tray notification on CHANNEL_SYSTEM

KycViewModel.init [NEW collector in WS-C]
  └─ kycStatusEventBus.events.collect
       └─ KYC_VERIFIED → navigate to home (onComplete callback)
       └─ KYC_REJECTED → KycUiState.Error with server-provided message
```

### PAN upload queue survives process death

`PHOTO_UPLOAD_RETRY` is persisted to Room via `PendingActionStore.upsert(…)`. When the process
restarts and the technician returns to `KycScreen`:

- `KycViewModel.init` observes `pendingActionStore.observeActive(userId)` filtered by type.
- If a `PHOTO_UPLOAD_RETRY` row exists for this `techId`, `photoUploadRetryPending = true`.
- `KycScreen` surfaces `PhotoUploadRetryBanner` — a non-blocking strip above the form card.
- Tapping "Retry" calls `viewModel.retryPhotoUpload()`, which replays the last URI from the
  pending-action `entityId` field and calls `KycOrchestrator.submitPan(…)` again.

```kotlin
public data class KycStatusEvent(
    val technicianId: String,
    val verified: Boolean,
    val rejectionReason: String? = null,
)

@Singleton
public class KycStatusEventBus @Inject constructor() {
    private val _events = MutableSharedFlow<KycStatusEvent>(extraBufferCapacity = 1)
    public val events: SharedFlow<KycStatusEvent> = _events.asSharedFlow()
    public fun post(event: KycStatusEvent) { _events.tryEmit(event) }
}
```

### WS-B — FCM: `HomeservicesFcmService` new KYC branches

Inject `kycStatusEventBus: KycStatusEventBus` alongside existing injected fields.

Insert **before** the legacy `JOB_OFFER` branch in `handleMessageData`:

```kotlin
"KYC_VERIFIED" -> {
    val techId = data["techId"] ?: return
    kycStatusEventBus.post(KycStatusEvent(techId, verified = true))
    showKycStatusNotification(verified = true, data["title"], data["body"])
}
"KYC_REJECTED" -> {
    val techId = data["techId"] ?: return
    val reason = data["reason"]
    kycStatusEventBus.post(KycStatusEvent(techId, verified = false, rejectionReason = reason))
    showKycStatusNotification(verified = false, data["title"], data["body"])
}
"ONBOARDING_REMINDER" -> {
    showOnboardingReminderNotification(data["title"], data["body"])
}
```

`showKycStatusNotification(verified, title?, body?)` — private helper posting on `CHANNEL_SYSTEM`:
- Title: `title ?: getString(if (verified) R.string.kyc_verified_notification_title else R.string.kyc_rejected_notification_title)`.
- Body: `body ?: getString(if (verified) R.string.kyc_verified_notification_body else R.string.kyc_rejected_notification_body)`.
- PendingIntent: `MainActivity` with `Intent.ACTION_MAIN` (KYC deep-link is future scope).

`showOnboardingReminderNotification(title?, body?)` — private helper posting on `CHANNEL_SYSTEM`.

**C3 — `OnboardingScreen` offline chip**

`OnboardingScreen` is currently stateless. Wire in a minimal `OnboardingViewModel`:

```kotlin
@HiltViewModel
public class OnboardingViewModel @Inject constructor(
    private val pendingActionStore: PendingActionStore,
    sessionManager: SessionManager,
) : ViewModel() {
    private val techId = sessionManager.currentTechnicianId ?: ""
    private val _kycSubmitQueued = MutableStateFlow(false)
    public val kycSubmitQueued: StateFlow<Boolean> = _kycSubmitQueued.asStateFlow()

    init {
        viewModelScope.launch {
            pendingActionStore.observeActive(techId).collect { actions ->
                _kycSubmitQueued.value =
                    actions.any { it.type == PendingActionType.KYC_SUBMIT_PENDING }
            }
        }
    }
}
```

In `OnboardingScreen`, add:
```kotlin
val vm: OnboardingViewModel = hiltViewModel()
val kycQueued by vm.kycSubmitQueued.collectAsStateWithLifecycle()
if (kycQueued) {
    Text(
        text = stringResource(R.string.onboarding_kyc_queued_offline),
        style = MaterialTheme.typography.labelSmall,
        color = MaterialTheme.colorScheme.onSurfaceVariant,
        modifier = Modifier.padding(horizontal = 20.dp),
    )
}
```
