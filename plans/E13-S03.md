# E13-S03 — No-Show Banner + FCM Branch Handler
**Tier:** Feature | **Ceremony:** lean (brainstorm embedded)
**Dependencies:** E13-S02 (WalletBalanceChip / WalletViewModel), E11-S01b-1 (FCM service refactor)
**Blast radius:** moderate — new event bus, one FCM branch, two screen modifications (composition only, no state changes), no DB schema changes

## Brainstorm (embedded)

**Design question 1 — event bus shape**
`PriceApprovalEventBus` / `RatingPromptEventBus` use `MutableSharedFlow<String>` where the
string is an entity ID.  For the no-show credit we also need the `creditAmountPaise` long so
the banner can format it.  Options: (a) a data class event, (b) a `Pair<String,Long>`,
(c) two separate fields on the flow.  **Decision: data class `NoShowCreditEvent`** —
self-documenting, easy to extend (e.g. `bookingId`), same pattern the team will follow for
future typed events.

**Design question 2 — WalletViewModel refresh trigger**
`WalletViewModel` lives in the HomeScreen NavBackStackEntry (created in `homeDestination`).
The FCM service runs in a background coroutine scope — it cannot hold a reference to the
ViewModel.  Options: (a) a second `SharedFlow` that WalletViewModel collects from init(),
(b) re-use `NoShowCreditEventBus` — WalletViewModel collects events and calls `retry()`,
(c) WorkManager deferred refresh.
**Decision: (b)** — WalletViewModel injects `NoShowCreditEventBus` and collects in a new
`collectNoShowEvents()` coroutine started in `init`. This keeps the pattern consistent, stays
DI-injected, and adds zero new infrastructure.

**Design question 3 — banner dismiss timer**
`LaunchedEffect` with `delay(5_000)` inside the `if (showBanner)` block. On recomposition
or tap the state `showBanner` flips to false. No `CoroutineScope` leaks because
`LaunchedEffect` is tied to the composable's lifecycle.

**Known gotchas referenced from docs/patterns/**
- firebase-callbackflow-lifecycle.md: not relevant here (no callbackFlow); FCM data arrives
  via `onMessageReceived` which is already dispatched on a background thread by the SDK.
- paparazzi-cross-os-goldens.md: Paparazzi methods are `@Ignored`; no goldens committed.
- kotlin-explicit-api-public-modifier.md: ALL new public declarations must carry `public`.

### WS-B — FCM: `CustomerFirebaseMessagingService` branch

Add `NO_SHOW_CREDIT_ISSUED` handling **before** the legacy `bookingId ?: return` gate — this
type does NOT require bookingId for the legacy path and should never fall into `return`:

```kotlin
if (data["type"] == "NO_SHOW_CREDIT_ISSUED") {
    handleNoShowCredit(data)
    return
}
```

`handleNoShowCredit(data)`:
1. Parse `creditAmountPaise` (`toLongOrNull() ?: 0L`) and `bookingId` (nullable).
2. `noShowCreditEventBus.post(NoShowCreditEvent(creditAmountPaise, bookingId ?: ""))`.
3. Post system-tray notification on `CHANNEL_CREDITS` — title from
   `data["title"] ?: getString(R.string.no_show_credit_notification_title)`, body from
   `data["body"] ?: getString(R.string.no_show_credit_notification_body)`.
4. PendingIntent opens `MainActivity` with `Intent.ACTION_MAIN` (no deep-link for now;
   wallet deep-link is E13-S04 scope).

Inject `noShowCreditEventBus: NoShowCreditEventBus` via Hilt.

**TDD:** `CustomerFirebaseMessagingServiceNoShowTest` — construct service manually with
MockK-mocked `NoShowCreditEventBus`; verify `post()` called with correct event; verify
notification manager `notify()` called once.

### WS-D — Screen wiring: `CustomerBookingsScreen` + `LiveTrackingScreen`

Both screens get identical wiring (no ViewModel change needed — event bus injected directly
via a new `NoShowBannerState` helper or collected in screen composable via
`rememberNoShowBannerState(eventBus)`).

To keep composable functions clean and avoid injecting event buses directly into screens,
introduce `NoShowCreditViewModel`:

```kotlin
@HiltViewModel
public class NoShowCreditViewModel @Inject constructor(
    private val eventBus: NoShowCreditEventBus,
) : ViewModel() {
    private val _event = MutableStateFlow<NoShowCreditEvent?>(null)
    public val event: StateFlow<NoShowCreditEvent?> = _event.asStateFlow()

    init {
        viewModelScope.launch {
            eventBus.events.collect { e -> _event.value = e }
        }
    }

    public fun dismiss() { _event.value = null }
}
```

`CustomerBookingsScreen` — at the top of its `Box`/`Column`:
```kotlin
val noShowVm: NoShowCreditViewModel = hiltViewModel()
val noShowEvent by noShowVm.event.collectAsStateWithLifecycle()
Box(modifier) {
    CustomerBookingsContent(...)
    noShowEvent?.let { evt ->
        NoShowCreditBanner(
            creditAmountPaise = evt.creditAmountPaise,
            onDismiss = noShowVm::dismiss,
            modifier = Modifier.align(Alignment.TopCenter),
        )
    }
}
```

Same pattern for `LiveTrackingScreen` — banner overlaid at `TopCenter` of the Scaffold
body, not inside the TopAppBar.

**WalletViewModel refresh** — add to `WalletViewModel`:
```kotlin
@Inject private lateinit var noShowCreditEventBus: NoShowCreditEventBus
// in init:
viewModelScope.launch {
    noShowCreditEventBus.events.collect { retry() }
}
```
Wait — `WalletViewModel` uses constructor injection, not field injection.  Correct approach:
add `noShowCreditEventBus: NoShowCreditEventBus` as constructor parameter.

**Note:** `CustomerBookingsScreen` is currently `internal fun`.  `NoShowCreditViewModel`
is injected via `hiltViewModel()` inside the same file — visibility is fine.
