# E16-S04 — Customer-app Address Picker (Places + Draggable Pin + Service-Area Refusal)

**Tier:** Foundation | **Deps:** E16-S01 (server-side polygon — already merged W1) | **Security trigger:** Yes (geo PII, spoofing surface)

Replaces the legacy `AddressScreen.kt` (current free-text + reverse-geocode pattern) with a Places-autocomplete + draggable-pin picker, runs a client-side polygon check as defence-in-depth, and routes out-of-area customers into a `WaitlistScreen` that posts to a new `POST /v1/waitlist` Azure Function. Design is **LOCKED** per `docs/superpowers/specs/2026-05-16-week5-foundation-stories-design.md` §3 — do not redesign.

## Architecture overview

Three layers, one new endpoint:

1. **UI (customer-app):**
   - `AddressPickerScreen` replaces the legacy `AddressScreen.kt`. Search field on top → `LazyColumn` of predictions → `GoogleMap` with one draggable `Marker` initialised at the selected place → primary CTA "Confirm address" OR refusal banner ("We don't serve this area yet" + secondary CTA → `WaitlistScreen`).
   - Strings localised EN + HI (Ayodhya/UP pivot — `feedback_pivot_ayodhya_hindi.md`).
   - `WaitlistScreen` is a single form: pre-fills the authenticated phone number, accepts edit, captures lat/lng + serviceId from the navigation arg, posts to `/v1/waitlist`, shows confirmation state.

2. **Domain / data (customer-app):**
   - `LocalServiceAreaCheck` is a pure utility — loads the Ayodhya polygon from `app/src/main/assets/service-area-ayodhya.geojson` once at app start, exposes `isInside(lat, lng): Boolean`. JVM-testable, no Android dependencies beyond `AssetManager` (which is `@Provides` from Hilt).
   - `PlacesClient` is injected via a new `PlacesModule.kt` (Hilt, Singleton scope). A new `PlacesAutocompleteUseCase` wraps `findAutocompletePredictions` and `fetchPlace` with **session tokens** (required for bundled Places SDK pricing — one token per autocomplete-then-select trip). `AutocompleteSessionToken.newInstance()` is generated per ViewModel lifecycle and rotated on every successful "select".
   - `AddressPickerViewModel` owns `AddressPickerUiState` (sealed): `Idle`, `Searching(query, predictions)`, `Selected(formattedAddress, lat, lng, isInService)`, `RefusedOutOfArea(lat, lng)`, `Error(reason)`. Marker drag end → 500ms debounce → `Geocoder.getFromLocation` (falling back to "Location set — confirm pin" string when geocoder unavailable).

3. **API (`api/`):**
   - New Azure Function `api/src/functions/waitlist.ts` — `POST /v1/waitlist` — Zod-validated body `{ phone, lat, lng, serviceId, requestedAt }`. Writes one Cosmos doc to `customer_waitlist` (partition `/phone`).
   - Admin read endpoint `GET /v1/admin/waitlist?page=&limit=` defers to **W6** to keep this plan under the 600-line budget. Plan flags the deferral; backlog row added in `docs/stories/README.md`.

The server-side polygon in `POST /v1/bookings` (E16-S01 / ADR-0020) remains **authoritative**. The client polygon is defence-in-depth + UX — saves the round-trip when the customer is clearly outside Ayodhya.

## Security invariants

- **Maps API key never committed.** `MAPS_API_KEY` is sourced from `System.getenv("MAPS_API_KEY")` or `local.properties` (already wired in `app/build.gradle.kts` — keep as-is). BuildConfig string field + `manifestPlaceholders["MAPS_API_KEY"]` already exist. New work: enable the Places SDK on the same key in Google Cloud Console (runbook entry, not a code change).
- **Client polygon is defence-in-depth only.** ADR-0020 is unchanged: server `POST /v1/bookings` runs the authoritative check via Turf.js. Threat-model T-B1 row remains valid; this story adds a row to the threat-model addendum confirming "client-side refusal is UX-only, server-side gate is unchanged".
- **Waitlist endpoint hardening:**
  - Zod schema: `phone` matches `^\+91[6-9]\d{9}$` (Indian mobile), `lat ∈ [-90,90]`, `lng ∈ [-180,180]`, `serviceId` is a known catalogue id (validated against catalogue cache), `requestedAt` ISO-8601 within ±90s of server clock.
  - Rate-limit middleware: **5 req per phone per hour, 50 req per IP per hour.** Uses the in-memory token-bucket already present at `api/src/middleware/rateLimit.ts` (extend with a `waitlist` bucket). 429 on exceed.
  - No auth required (the customer hasn't signed up yet — that's the whole point), so spoofing risk is real. Mitigation: rate-limit + phone format validation + serviceId allow-list. Cosmos doc carries `sourceIp` (from `x-forwarded-for`, last hop) for forensic review.
- **PII surface:** waitlist stores phone + lat/lng. New row in `docs/threat-model.md` addendum: **I-W1 — waitlist PII exposure**. Mitigations: admin-only read, no FCM emit, Cosmos at-rest encryption, 365-day TTL on waitlist docs (compliance retention).
- **/security-review is mandatory** (geo PII + new public endpoint).

**File 2 (impl):** `customer-app/app/src/main/kotlin/com/homeservices/customer/domain/serviceArea/LocalServiceAreaCheck.kt`

```
public class LocalServiceAreaCheck @Inject constructor(
    @ApplicationContext context: Context,
) {
    private val polygon: GeoJsonPolygon = loadPolygonFromAssets(context, "service-area-ayodhya.geojson")
    public fun isInside(lat: Double, lng: Double): Boolean = pointInPolygon(lat, lng, polygon)
}
```

Implementation notes:
- Ray-casting algorithm (same algorithm Turf.js uses) — vertex inclusive for parity with server. **No external dep** — pure Kotlin, ~30 lines.
- `GeoJsonPolygon` is an internal data class holding the ring coordinates as `List<Pair<Double, Double>>` (lng, lat per GeoJSON convention).
- Asset parsing: org.json (already on the classpath via the Android SDK) — no Moshi dep needed for this single load.
- Polygon cached as a class-level property — single load per process.

**Hilt binding:** singleton in `PlacesModule` (WS-C) — `@Provides @Singleton fun provideLocalServiceAreaCheck(@ApplicationContext ctx: Context): LocalServiceAreaCheck`.

## ADR / threat-model notes

- **No new ADR.** ADR-0020 already covers the polygon-based service-area gating. This story bundles a client-side defence-in-depth copy but does not introduce a new architectural decision.
- **Threat-model addendum (committed in this PR):**
  - **T-B1 (client-bypass of service area):** confirmed unchanged. Server-side polygon in `POST /v1/bookings` remains authoritative; client check is UX-only.
  - **I-W1 (waitlist PII):** new row. Surface = `POST /v1/waitlist` (anonymous endpoint). Data = phone + lat/lng. Mitigations = Zod phone format validation, rate-limit (5/hour/phone, 50/hour/IP), SHA-256 hashed phone in logs, Cosmos at-rest encryption, 1y TTL, admin-only read (deferred to W6).
  - **S-A2 (spoofed lat/lng in waitlist):** acceptable residual risk — waitlist has no monetary value to spoof; rate-limit caps the abuse blast radius. Document in the row.
